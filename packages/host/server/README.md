# `@workbench/host-server`

Node-only HTTP and WebSocket ingress for a Workbench Runtime Host. The package accepts application-provided HTTP, WebSocket, lifecycle, and non-Runtime upgrade relay ports; it does not construct an application or business gateway.

The public modules are `./workbench-http-server`, `./runtime-transport-auth`, `./fetch-request-handler`, `./api-only-runtime-host`, and `./runtime-host-control-session`. The ingress applies the shared request-trust fence, dispatches runtime-owned upgrades, and delegates non-runtime upgrades to an optional application relay. The transport-auth module owns desktop-sidecar HTTP bearer/CORS admission and the versioned WebSocket first-frame authentication boundary. A direct desktop renderer still authenticates with that first frame. The Runtime-connected Web Host instead admits the public same-origin Upgrade first and injects its in-memory Bearer only on the private Runtime hop; the Runtime Host converts that validated Upgrade into a request-bound, one-use authorization, so neither an authentication frame nor its acknowledgement crosses the public socket. Independently canonicalized listener and gateway policies must match every authority field before that authorization can be consumed. The Fetch carrier streams request and response bodies without buffering, preserves outer Host-owned `Access-Control-*` response headers, and merges `Vary` tokens without duplication. The API-only assembly adds authenticated generic health/identity endpoints but still receives every business handler and gateway from its application composition root.

This leaf may depend only on `@workbench/server-core`, `@workbench/host-contracts`, and explicit Node/WebSocket types. Runtime composition remains responsible for choosing and injecting handlers, relays, business gateways, and one lifecycle. An API-only composition must build every injected WebSocket gateway with the same `desktopSidecarAuth` authority fields so transport authentication—either the direct-renderer first frame or a validated private-hop Upgrade—completes before any business allocation. API-only shutdown stops accepting new traffic before invoking the lifecycle; the lifecycle must close all already-upgraded WebSockets and dispose its service graph before resolving. One positive `deadlineMs` bounds HTTP closure and lifecycle disposal together, and the lifecycle receives an `AbortSignal` when it expires. Expiry rejects shutdown and therefore cannot produce a control acknowledgement; the external Runtime process owner remains responsible for forcibly terminating an uncooperative child. A control acknowledgement is emitted only after both lifecycle disposal and HTTP closure complete.

The NDJSON session consumes the separate `@workbench/host-contracts/runtime-host-control` protocol. Its output `Writable` owns Host stdout exclusively: the Runtime process entry must prevent direct `process.stdout.write` calls from application or third-party code, and all logs belong on stderr. The package-level session does not mutate process globals or mechanically fence stdout. It emits only schema-created credential-free frames and closes a started Host after malformed input, stdin disconnect, iterator failure, or output failure.
