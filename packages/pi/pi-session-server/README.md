# @workbench/pi-session-server

src owns hosted sessions, registries, journals, history, attachments, imports, automation and Agent adapters. lib supplies consumed projections, context formatting, usage aggregation and source parsing. Sources are TS, at most one directory level per root. createPiSessionRegistry receives publisher and host/resource/tool collaborators from server composition, once per server module generation. Existing process registry, SDK session lifetimes, interactive Symbol identity and shutdown hooks remain owned by this package. Service defaults are explicit; server composition selects concrete registry callbacks. Pure helper tests live in tests and host integration in pi/server.

The process-retained registry state is composed from focused live-session, persisted-directory,
scratch-session, and fork-serialization owners. They retain one HMR-stable state graph; the registry
facade coordinates behavior without creating another SDK session, lock, cache, or cleanup lifecycle.

Source layout: src owns this capability and its contracts; lib contains consumed internal helpers; tests live at the package root. Example consumer: `src/composer-conversation-context.ts` imports `lib/composer-conversation-context.ts`. Capability and helper code remains TS/TSX; existing build tooling retains its language.

Spec008 separates `hosted-pi-session.ts` from registry composition. It remains the sole SDK session/event/queue owner and receives explicit publisher, notification, interaction, model-revision, composer-command, history-reader and file-reader operations. `session-projections.ts` shares the original history/resume/metadata and message projection rules between live and cold readers; `session-types.ts` holds their internal contracts. `hosted-session-lifecycle.ts` and `session-mutations.ts` own shutdown and per-session serialization. `persisted-session-directory.ts` and `scratch-session-directory.ts` own catalog mutations and scratch expiry/file cleanup. Process state and fork serialization remain in `session-registry-state.ts`, retaining the exact maps, timers and promise tails during HMR adoption. Public registry methods and stable protocol IDs remain unchanged.
