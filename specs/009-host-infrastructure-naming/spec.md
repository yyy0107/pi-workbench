# Feature Specification: 明确应用基础设施能力归属

**Feature Branch**: `codex/package-refactor`

**Created**: 2026-09-13

**Status**: Accepted

**Input**: 用户要求优化 packages/host，使连接、进程管理和构建产物能力容易查找，延续前轮命名与 README 整理。

## User Scenarios & Testing

### User Story 1 - 按能力找到入口 (Priority: P1)

维护者从包导航找到连接服务、应用进程管理和构建产物能力，并知道如何使用。

**Why this priority**: 当前 Host 同时表示连接、进程和扩展容器，查找需要额外理解历史命名。

**Independent Test**: 静态核对导航、职责、公开入口与源码位置。

**Acceptance Scenarios**:

1. **Given** 维护者需要连接后台，**When** 阅读包导航，**Then** 能找到客户端与服务端对应的传输能力及其共享合同。
2. **Given** 维护者需要启动或关闭后台，**When** 阅读进程能力说明，**Then** 能找到控制会话、子进程和就绪探测入口。
3. **Given** 维护者需要校验构建产物，**When** 阅读构建领域说明，**Then** 能区分产物读取与准入规则。

### User Story 2 - 独立复用基础能力 (Priority: P2)

维护者可独立引用网络传输或构建产物能力，不引入应用进程装配。

**Why this priority**: 名称应对应真实依赖边界。

**Independent Test**: 检查公开入口与依赖方向，并执行相关非界面行为测试。

**Acceptance Scenarios**:

1. **Given** 一个只需要处理连接的消费者，**When** 引入网络能力，**Then** 不依赖进程管理或产物规则。
2. **Given** 一个只读取产物的消费者，**When** 引入产物读取能力，**Then** 不依赖网络服务或产品业务。

### User Story 3 - 升级后保持行为兼容 (Priority: P1)

现有 Web、Desktop、Runtime 应用在目录和导入迁移后仍然可以构建，并保持原有服务行为。

**Why this priority**: 命名调整不应影响认证、通信、进程退出或已有产物格式。

**Independent Test**: 类型与依赖检查、精选非界面测试和完整构建。

**Acceptance Scenarios**:

1. **Given** 已有应用和协议，**When** 完成迁移，**Then** 认证、控制消息、资源与产物格式保持兼容。
2. **Given** 任意仓内消费者，**When** 检查其导入和文档，**Then** 全部指向实际存在的公开入口。

### Edge Cases

- 构建脚本使用不同模块格式，迁移保留原加载方式。
- 同一消费者同时使用传输、进程和产物能力，分别声明直接依赖。
- 共享合同包含连接、宿主能力、进程控制和产物格式，说明中明确分类，不把它误标为浏览器专属。
- 历史规格与验证记录保留完成时名称；当前导航说明最新映射。

## Requirements

### Functional Requirements

- **FR-001**: 目录与包名必须明确区分传输、进程管理、产物读取和产物策略。
- **FR-002**: 相关客户端和共享合同必须有明确的领域归属。
- **FR-003**: 每项公开能力必须有唯一拥有者，所有仓内消费者同步迁移，不保留兼容空壳。
- **FR-004**: 新边界必须形成无环依赖，基础传输与产物读取不得依赖应用进程管理。
- **FR-005**: 稳定协议、认证、控制消息、持久化和产物格式必须保持兼容。
- **FR-006**: 受影响包必须提供中英文职责说明、完整公开入口与源码导航。
- **FR-007**: 相关非界面行为测试、类型、结构、依赖和构建检查必须通过才能记录完成。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 三类查找场景均可从包导航进入对应能力说明，并找到使用入口。
- **SC-002**: 迁移范围内全部公开能力与文档入口对应，无丢失或重复拥有者。
- **SC-003**: 所有受影响消费者使用有效入口，基础能力无反向依赖或依赖环。
- **SC-004**: 现有相关非界面行为检查全部通过，三个应用的构建全部成功。

## Assumptions

- 本次范围是现有 Host 基础设施及其直接引用；扩展平台、Pi 业务、界面和本地文件能力的职责保持原状。
- 延续用户约束：不新增或运行 UI/DOM/Hook 渲染测试或界面冒烟。
- 使用现有依赖与工具链，不升级第三方版本；历史 Spec001–008 保持原记录。

## Workbench 项目约定

遵循项目宪章和 AGENTS.md：两级能力包目录、浅层 src/lib、明确 exports、pnpm、包根 tests。只在验证后记录完成。
