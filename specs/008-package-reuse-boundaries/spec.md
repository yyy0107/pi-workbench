## User Scenarios & Testing _(mandatory)_

### User Story 1 - 使用能力时只依赖必要边界 (Priority: P1)

作为能力维护者，我希望通过明确的输入、输出和生命周期使用浏览器、文件及会话协作能力，替换实现时不必修改调用方或引入它不需要的服务。

**Why this priority**: 包目录与无环依赖仍可能掩盖共享边界对具体实现的依附，阻碍替换、验证和复用。

**Independent Test**: 为浏览器命令、文件读取、工作区会话协作提供最小替身，不创建实际服务实例即可验证约定及取消、失败行为。

**Acceptance Scenarios**:

1. **Given** 消费者只需要浏览器命令或文件读取，**When** 更换提供者，**Then** 能力约定不随具体服务类变化，也不要求加载该服务。
2. **Given** 消费者只需要关联或移除会话，**When** 工作区内部实现变化，**Then** 消费者只受所需操作的约定约束，不获得整个工作区服务。
3. **Given** 可选能力未提供或请求已取消，**When** 调用相关操作，**Then** 保持原来的不可用、取消及错误语义，不隐式创建第二套服务。

---

### User Story 2 - 在多个界面复用文件呈现 (Priority: P1)

作为附件、消息和文件浏览功能的维护者，我希望复用文件图标和保存行为，而无需安装文件树、工作区控制器或整个应用外壳。

**Why this priority**: 已有多个真实消费者，能够据此定义共享边界，无需为假设性需求设计抽象。

**Independent Test**: 静态核对附件、消息图片和文件树共用相应实现，检查独立入口及资源供应；只运行文件名和图标映射等非 UI 逻辑验证。

**Acceptance Scenarios**:

1. **Given** 附件列表只需文件图标，**When** 独立使用该能力，**Then** 无需文件树或工作区状态即可获得原有图标映射、默认回退和主题资源。
2. **Given** 消息图片与文件浏览提供保存功能，**When** 复用下载能力，**Then** 文件名、保存取消、错误和资源释放规则保持一致，并保留原来的用户操作时机。
3. **Given** 应用采用不同主题、密度、圆角或资源地址，**When** 装配该能力，**Then** 继续使用共享外观和资源约定，不要求复制业务样式。

---

### User Story 3 - 单独使用工作区状态和持久化 (Priority: P1)

作为不同宿主与运行时的维护者，我希望复用工作区面板状态，以及项目目录、会话归属、排序和归档规则；这些能力各有明确所有者，无需启动某个 Agent 产品或挂载界面。

**Why this priority**: 呈现与产品协议不应成为使用公共工作区规则的前提。

**Independent Test**: 分别在无界面环境验证面板打开、恢复、关闭，以及项目目录创建、会话移动、归档和旧数据读取；不合并成一个工作区总服务。

**Acceptance Scenarios**:

1. **Given** 只使用面板状态与恢复规则，**When** 在不挂载界面时运行，**Then** 不需要呈现组件、应用安装上下文或界面副作用。
2. **Given** 只使用项目目录、排序与会话归属，**When** 最小会话目录能力提供已有会话，**Then** 不需要 Pi 资源加载器或 Pi 消息发布器。
3. **Given** 已有固定项、归档项及跨进程更新，**When** 更换能力归属，**Then** 持久化格式、路径、修订与互斥规则不变，每次变化只发出一次应有通知。
4. **Given** 不同安装实例或临时会话转为正式会话，**When** 恢复、提升作用域或销毁，**Then** 按原规则隔离状态，草稿、待提交反馈与面板身份不丢失、不串用。

---

### User Story 4 - 分别维护会话目录、运行和消息恢复 (Priority: P1)

作为会话维护者，我希望目录管理、运行中的会话、历史恢复、附件提交和交互请求具有可独立理解与验证的职责，修改一项无需访问其他职责的全部内部状态。

**Why this priority**: 客户端与服务端会话核心集中处理多类状态，重连、排队、恢复和销毁容易相互影响。

**Independent Test**: 使用既有事件和请求记录分别验证目录变化、附件提交、历史合并、队列与恢复，再用非 UI 集成验证它们共用原来的权威会话和连接。

**Acceptance Scenarios**:

1. **Given** 会话目录需要重载，**When** 验证目录和工作区归属，**Then** 不必初始化附件上传、输入草稿或模型输出处理。
2. **Given** 已有历史、流式消息和队列，**When** 重连、旧响应晚到或重载，**Then** 消息身份、顺序、去重、分支及运行状态与重构前一致。
3. **Given** 正在提交附件或等待交互，**When** 取消、失败或销毁，**Then** 按原规则处理反馈认领与释放、临时资源和订阅，不重复执行请求。
4. **Given** 同一宿主内存在多个会话，**When** 调整职责组织，**Then** 不增加连接、注册表或权威状态副本，事件顺序及互斥边界不变。

---

### User Story 5 - 用证据约束后续拆分 (Priority: P2)

作为项目维护者，我希望每项拆分说明实际问题、现有消费者、收益与退出条件，同时保留合理装配，避免只增加包数量。

**Why this priority**: 前几轮已提取较多能力，下一轮应依据真实复用和变更边界收敛职责。

**Independent Test**: 对照发现与依赖基线，逐项核对来源、消费者、所有者、验收方式和保留项。

**Acceptance Scenarios**:

1. **Given** 候选只有文件过大而无独立复用需求，**When** 制定方案，**Then** 优先包内拆分，不以行数决定新增包。
2. **Given** 已有两个消费场景或独立运行需求，**When** 决定提取，**Then** 记录唯一所有者、最小约定和全部消费者迁移范围。
3. **Given** 既有基础能力或装配符合职责，**When** 审查依赖，**Then** 保留合理关系，不复制通信、持久化、国际化、控件或安装机制。

### Edge Cases

- 类型引用不产生运行时加载，但仍绑定到具体实现：分别评价契约与加载耦合。
- 小能力经过同时导出完整界面的聚合入口：沿实际入口检查，不能只看包名。
- 图标资源缺失、加载失败或没有浏览器对象：保持原有默认和延迟访问行为。
- 归档、固定、排序与会话目录并发变化：保留事务和锁，不允许拆分后互相覆盖写入。
- 旧文档迁移失败或写入成功但通知失败：保留提交状态与原恢复规则，不重复迁移。
- 重连、分支、取消及历史响应交错：只接受正确代次的结果，保持消息身份和序列。
- 安装替换或销毁后请求仍完成：保留延迟解析与失效判断，不将旧实例重新绑定。

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: MUST 建立全部现存库包的职责与依赖基线，为本期发现提供源码证据；不得将设计风险说成已发生的运行故障。
- **FR-002**: MUST 使浏览器命令、文件读取和工作区会话协作约定独立于具体服务实现，消费者仅获得必要操作。
- **FR-003**: MUST 保持所收窄能力的取消、错误、可选回退和生命周期，不增加隐式实例。
- **FR-004**: MUST 让附件、文件树与消息图片经明确入口共用文件呈现能力；图标和下载使用不得要求文件树、工作区控制器或整个 Shell 实现。
- **FR-005**: MUST 保持资源定位、图标回退、保存时机和资源清理，继续接入原有主题、密度、圆角与国际化。
- **FR-006**: MUST 分开工作区面板状态、恢复、反馈规则和界面呈现，使状态能力可无界面使用。
- **FR-007**: MUST 将项目目录、会话归属、固定、排序和归档从 Pi 资源管理职责分离，核心不依赖 Pi 资源加载或流式协议。
- **FR-008**: MUST 保持工作区持久化格式、键、迁移、锁、修订、事件与实例隔离；Pi 协议适配仍由 Pi 所有者负责。
- **FR-009**: MUST 明确会话目录、运行、历史恢复、附件提交和交互请求的唯一状态所有者及最小协作约定，不传递整个管理器或注册表作为通用依赖。
- **FR-010**: MUST 保持唯一权威会话、连接复用、互斥、消息顺序、历史去重、分支、队列和取消语义；继续使用已提取能力。
- **FR-011**: MUST 为提取记录至少两个现存消费场景或独立运行需求；只有规模问题时优先包内拆分。
- **FR-012**: MUST 同步迁移全部仓内消费者、入口、资源、测试归属和双语文档，删除本期替代的旧入口与临时转发。
- **FR-013**: MUST 保持扩展对象、稳定标识、安装顺序、通信方法和持久化兼容；合理产品装配关系不属于强制消除项。
- **FR-014**: MUST 建立所选边界的静态回归约束，执行必要非 UI 行为验证、类型、结构、依赖检查和受影响构建；不新增或执行 UI、DOM、Hook 渲染及交互冒烟。
- **FR-015**: MUST 分开记录规格质量与实施结果，未实施的复用或兼容结果不得标完成；初轮只交付审查和规格，后续授权实施必须按任务记录真实验证状态。

### Key Entities _(include if feature involves data)_

- **能力边界**：职责、输入、操作、所有者与生命周期，不绑定具体提供者内部实现。
- **复用候选**：具备来源证据、真实消费者、提取理由、保留行为和退出条件的一组能力。
- **面板状态**：面板身份、作用域、布局、草稿与反馈，按安装实例隔离。
- **项目会话目录**：项目路径、会话归属、固定、顺序与归档，保留持久化身份。
- **会话协作约定**：五类职责间的必要操作，权威状态只归一个所有者。
- **验证证据**：关联具体需求和场景的静态、非 UI 验证及真实完成状态。

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: 基线覆盖全部 94 个现存库包，本期每项发现都有来源、影响、优先级和处理决定。
- **SC-002**: 浏览器命令、文件读取、工作区会话协作三类边界均可由最小替身提供，无需依赖具体服务实现；对应边界检查全部通过。
- **SC-003**: 附件图标、文件树图标、消息图片保存三个场景完成复用；每种图标映射或下载规则仅保留一份实现，独立图标与下载入口不要求文件树或工作区控制器。
- **SC-004**: 面板状态与项目会话目录分别通过无界面验证，后者无需 Pi 资源与消息发布设施；旧数据迁移及事件兼容验收全部通过。
- **SC-005**: 会话目录、运行、历史恢复、附件提交和交互请求五类职责有唯一状态所有者及独立验证入口，US4 四类兼容场景全部通过，权威会话与连接实例数不增加。
- **SC-006**: 迁移消费者更新率 100%，本期禁用依赖及临时转发剩余为零；每个新增包都有真实消费者或独立运行理由。
- **SC-007**: 受影响非 UI、类型、结构、依赖与构建检查全部通过；新增和执行的 UI 测试均为零，未验证视觉交互明确记录。

## Assumptions

- 初轮交付为架构分析与规格；用户随后要求“开始执行”，现按 plan.md 与 tasks.md 实施，原候选映射由最终合同细化。
- 基线提交为 `f95cc7379a42e30e9a1b03aa149e45d1f4c0af2b`。已有技能文件修改不属于本期；Spec 001–007 原记录保留。
- 优先现有能力和公开子入口。94 是基线，不是强制包数，不设置增包目标。
- 不引入新的插件加载、状态、通信、持久化、国际化或权限框架，不升级 SDK 或构建系统。
- 浏览器、模型、专用界面的大文件拆分及工具输出预算问题记录为后续候选，不混入本期兼容性迁移。
- 既有 UI 测试可以迁移和静态审查，但不新增、不执行；用户约束优先于宪法的一般冒烟要求。
- 技术落点和顺序已由 `speckit-plan` 冻结于 [实施计划](plan.md)；[架构审查](architecture-review.md)与[候选映射](extraction-map.md)提供依据，不替代实施计划。
