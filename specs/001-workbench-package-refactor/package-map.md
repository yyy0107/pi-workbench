## 剩余装配归属

- Shell 保留主布局、侧栏核心流程、Panel Host、应用 Provider；brand/workspace-sidebar/archived-chats 与核心侧栏共置。
- Pi product 保留产品扩展顺序、公共与 Pi bundle 安装及平台适配。
- Pi contributions 只保留分组和 Provider 装配；Pi client 保留 manager/session 协调及能力适配。
- Pi server 保留 public、HTTP/RPC routes、WebSocket/StreamHub、host info 与 composition。
- 本表每个新增包都必须实际拥有实现；不能用空壳/全部转发或制造循环满足数量。
- 小型共用纯工具按实际消费者下沉到上述基础包；不新增通配 common 桶。

## 用户补充分工（constitution 3.1.0）

本表所有包使用 src（真实能力源码）、lib（内部辅助源码）、tests（测试），两处源码都最多一级子目录。公开入口在 src；业务实现、组件、契约、装配及所属词典/样式也在 src。lib 保留 TS/TSX，不能把整个能力搬进 lib。表中来源为历史路径；保留包名、ID、接口及行为。

```text
packages/<domain>/<capability>/
├── src/
│   ├── index.ts                 # 公开接口与必要装配
│   ├── service.ts               # 实际能力/服务
│   ├── types.ts                 # 能力契约
│   └── i18n/
│       ├── en-US.ts
│       └── zh-CN.ts
├── lib/
│   ├── normalize-input.ts       # service 使用的内部输入处理
│   └── typed-cache.ts           # 内部类型化缓存
├── tests/
└── package.json
```

这是职责示例，不要求每个包复制上述文件，也不按数量分配 src/lib。T053 的整批移动只是历史记录；T055 必须逐包重审已迁移 19 包，记录真实源码职责和 TypeScript 检查范围，T029 之后的任务及 T048 覆盖其余包。

### Composer / Conversation 分工细化

Composer 拥有编辑器、命令参数/Token、输入历史、附件预览与提交；`composer-message-text` 和 `composer-command-response` 是消息渲染器，随 T029 归 Conversation，避免 Composer 反向依赖消息 Context/CompactionSeparator。纯 agent-command 解析和旧指令兼容读取随 Composer；共享会话偏好存储归 settings-runtime 的明确子入口，保留同一安装级资源与保存行为。

### Conversation 迁移落实

Conversation 包同时拥有 message-presentation、message-actions、message-queue、user-message-index、todo-panel、interactive-requests、side-chat、archived-chats 的组件/扩展注册；Shell 仅按原数组顺序装配其公开入口。滚动持久化与标题裁剪归该包的 /scroll-state、/title，投影/布局/策略辅助归 lib。共享导航策略归 shell-context/navigation-policy，时长格式化归 i18n/duration，工具偏好存储归 settings-runtime/tool-capability-preferences；均保留 TS。
